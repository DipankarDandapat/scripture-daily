PART 2: CRITICAL ISSUE – VERSE CHANGES ON EVERY API REFRESH
==================================================

This is one of the most important requirements.

Currently, the Home page verse may change when:
- The user refreshes the Home page.
- The application is reopened.
- The Home screen is recreated.
- An API request is repeated.
- The user navigates between screens.
- The app makes multiple backend requests.

THIS BEHAVIOUR MUST BE FIXED.

A verse must never change simply because an API was called again.

The application must maintain ONE ACTIVE VERSE at a time for the current tradition and language.

### 1. Expected Verse Behaviour

Example:

The user selects:
- Tradition: Hinduism.
- Language: English.
- Verse Frequency: Every 6 hours.

At 10:00 AM:
- The backend selects one verse.
- This becomes the active verse.
- Home page displays that verse.
- Lock-screen wallpaper uses that verse.
- Home-screen widget uses that verse.

At 10:15 AM:
- User refreshes Home page.
- The same verse must be displayed.

At 10:30 AM:
- User closes and reopens the application.
- The same verse must be displayed.

At 11:00 AM:
- User navigates between Home, Saved, Explore and Settings.
- The same verse must remain active.

At 11:59 AM:
- User refreshes the Home page multiple times.
- The same verse must remain active.

At 12:00 PM:
- The configured 6-hour update cycle is reached.
- A new verse is selected automatically.
- Home page, lock-screen wallpaper and widget update to the same new verse.

The same behaviour must work for all supported traditions and languages.

### 2. Discover Another Verse – Explicit User Action

The existing "Discover another verse" button must remain functional.

Expected behaviour:

1. User opens Home page.
2. The currently active verse is displayed.
3. User clicks "Discover another verse".
4. The application explicitly requests a new verse.
5. Backend selects a new eligible verse.
6. The new verse becomes the active verse.
7. Home page displays the new verse.
8. Lock-screen wallpaper and widget synchronize with the new active verse.
9. The scheduled update timer restarts from the explicit selection time.

Only this explicit user action should manually change the active verse before the next scheduled update.

Do not change the verse when:
- Home page is refreshed.
- API is called again.
- App is reopened.
- User switches tabs.
- Widget is refreshed.
- Wallpaper is regenerated using the same verse.

### 3. Time-Based Verse Modes

Support the existing verse selection modes.

For example:
- Daily mode: Maintain one selected verse for the calendar day.
- Scheduled frequency mode: Maintain one active verse until the configured update interval expires.

In Daily mode:
- Do not select a different verse on every Home page visit.
- Keep the same verse throughout the day unless the user explicitly clicks Discover another verse.

In Scheduled frequency mode:
- Automatically change the active verse only when the configured interval expires or the user explicitly discovers another verse.

Changing the selected mode or frequency must be handled explicitly and must not accidentally trigger multiple verse selections.
